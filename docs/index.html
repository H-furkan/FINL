System Architecture

Three-layer hybrid retrieval with drug-aware document linking

User Query

"Which drug is used for asthma and what are its side effects?"

↓

Query Classifier

Routes to: drug_specific | condition_lookup | comparison | multi_hop | safety | general

↓
🎯

Layer 1: Drug Match

Regex extraction of drug names. Score: 1.0

📊

Layer 2: TF-IDF

Cosine similarity on cleaned text. Weight: 0.5

🔑

Layer 3: Keywords

Condition + side-effect reverse index. Score: 0.8

↓

Sibling Linker

Always pulls both usage + side-effect docs for matched drugs

↓

Enriched Context + LLM Generation

Raw docs + structured summaries from drug_knowledge.csv sent to LLM with few-shot prompts. Falls back to structured answers when LLM is unavailable.

Key Features

What makes this system stand out

🔬

Drug-Pair Structure Exploitation

We discovered the dataset has 50 drugs with exactly 2 docs each (usage + side effects). Our sibling linker exploits this structure directly, fixing failures that naive TF-IDF misses.

🤖

Query-Type-Aware Prompts

6 query types, each with optimized prompt templates and few-shot examples. The classifier routes queries to the right retrieval strategy before touching the LLM.

🛡

Hallucination Prevention

Unanswerable detection via score thresholding. When no document is relevant enough, the system refuses to answer rather than making things up. 100% on unanswerable queries.

⚡

Zero-LLM Fallback

Structured answers from drug_knowledge.csv when the API is down. Achieves 74% accuracy with zero LLM calls -- instant, free, always available.

📈

Knowledge Graph Visualization

Interactive networkx graph of all 50 drugs, 41 conditions, and 68 side effects. Drug-focused and condition-cluster views for presentation.

🎨

Multi-Model Gradio UI

Switch between 3 free LLMs (Qwen, Mistral, LLaMA) or retrieval-only mode from a dropdown. 10 example queries, source citations, query info panel.
